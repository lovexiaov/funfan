# FunFan 更新日志

本文件是 FunFan 发布说明（release notes）的「变更」段唯一人工维护来源。
`scripts/gen-release-notes.sh` 发版时会读取当前版本对应的 `## FunFan <版本>` 小节，
作为 GitHub Release 的「变更」内容；没有对应条目时回退到 git 提交记录。

> 约定：每个版本发布前在此补一条，用面向用户的话写「改了什么、为什么」，不要只抄提交标题。
> 安装 / 校验 / 系统要求等固定文案由脚本统一生成，不在此重复。

## 未发布

- 修「检查更新」总是提示限流：原来只走 GitHub 的接口，它对未认证请求**按 IP** 限每小时 60 次，共用同一出口（运营商大内网、公司网络、代理）时很容易被别的流量耗光。现在额度耗尽或连不上时会自动改用 GitHub 的发布订阅（没有这个配额），用户不会再看到「限流」二字——除非两个通道都不可用。改用订阅时少一个 `.dmg` 直链，点「下载」会打开发布页（页面上有安装说明、校验和与全部附件）

## FunFan 1.0.0-alpha.8 (2026-11-11)

- 新增「检查更新」（设置 → 更新）：点「检查更新」向 GitHub 查一次最新版本，结果显示在同一行；发现有新版本时上方会出现下载入口，菜单栏面板底部也会提示一行
- 可开「每天自动检查一次」（默认**关闭**）：打开后每天启动时查一次，只发送当前版本号，不含任何设备或使用信息；不开时只有点按钮才联网
- 只跳转下载页，不会自动下载或替换（未公证的包自替换会绕过系统的人工放行）；「忽略此版本」只跳过这一个版本，更新的版本仍会提示；检查失败会说明是哪一类原因（断网 / 接口限流并给出等待时间 / 格式变化）
- 新增「调速依据温度」设置（设置 → 风扇调速）：曲线与规则可以选按**最高温度**（默认，任一传感器过热就提速）或按**平均温度**（CPU 与 GPU 全部探测点的均温，SSD/电池/环境不参与）来调速。选平均温度后风扇更容易保持安静，代价是安全下限也按均温计算，单个热点的瞬时高温不再单独把转速顶满——想更保守就保持「最高温度」
- 设置页副标题与曲线编辑器都会显示当前口径的实际读数（最热 / 均温），避免「按均温调速、却按最热画线」
- 设置窗口改为可缩放、内容可滚动：此前固定高度会把「免责声明」整段裁掉

## FunFan 1.0.0-alpha.6 (2026-11-02)

- 重启后 helper 不自启现在会自动取证：刚开机窗口内（默认 10 分钟）检测到「文件都在但 launchd 没加载」时，自动生成一份带启动时间/距启动多久上下文的诊断报告落到 `~/Library/Application Support/FunFan/diagnostics/`，并弹一次提示（issue #1）
- 报告与「手动调试」区分开：只有真正刚重启后才触发自动取证，手动 `launchctl bootout` 调试不会误报
- 面板横幅与设置诊断区在「需重启修复」状态下都加了「诊断报告」按钮，一键在 Finder 打开刚生成的取证报告，方便回头发 issue
- 修复点状态栏图标「关不掉 / 点一下又弹回」：面板开着时点图标想关，系统在转交点击前会让 App 失活，旧的失活处理抢先把面板关掉，随后的开关判断就把这次点击误判成「打开」并重新弹出。现在失活关闭改为延迟执行且可被图标点击取消，一次点击就是一次干净的开关（首次点击同样稳定）
- 修复面板关掉再打开后「展开各核心温度」又变回收起态：该展开状态改为跨面板重开保留，关→开不再丢失

## FunFan 1.0.0-alpha.5 (2026-11-02)

- 面板打开时的采样频率进一步降低：从 1s 降到 2s，与「仅看菜单栏」同档，空闲时 CPU 占用几乎可忽略
- 新增两层采样：每 10 帧做一次全量扫描，其余帧只读每个温度类别里最热的 4 个键，单帧采样成本降低约 77%（真机 A/B：单帧 17.2ms → 4.0ms）
- 采样降频对温度读数的影响可忽略：加热态下最热键偏差 0.000℃、整体均温偏差 ≤0.022℃，且输出形状与全量一致，消费方零改动
- 配套：FunFanProbe 新增 `--tier` A/B 对比模式，可逐帧对比新旧采样策略的耗时、IPC 与温度偏差

## FunFan 1.0.0-alpha.4 (2026-11-01)

- 修复 popover 关闭后空闲 CPU 占用 12%+ 的问题（关闭时把 rootView 换成同尺寸空白占位，避免隐藏窗口仍在 60Hz 重排）

- 诊断报告新增「launchd 是否加载」判断，定位重启后不自启的根因（issue #1）
